================================================================================
RECRUITSAGE - NON-FUNCTIONAL REQUIREMENTS SPECIFICATION (NFRS)
================================================================================

1. PERFORMANCE & LATENCY
   1.1 Concurrent Multi-Agent Execution:
       - Web search queries (DuckDuckGo, Glassdoor snippets, Reddit discussions) 
         and campus DB vector retrieval MUST execute asynchronously and in parallel.
       - End-to-end dossier generation target: under 15–20 seconds on Apple Silicon M4.
   1.2 Interactive Chat Latency:
       - Local Ollama token generation for follow-up chat doubts MUST stream tokens 
         with a Time-To-First-Token (TTFT) < 1.0 second on M4 via Metal (MPS) acceleration.
   1.3 Extension Responsiveness:
       - Extension DOM extraction must complete within 200 milliseconds without 
         freezing or lagging the active Thapar portal tab.

2. PRIVACY & LOCAL-FIRST SECURITY
   2.1 Zero External Data Leakage:
       - 100% of LLM inference is performed locally via Ollama.
       - No student portal credentials, session tokens, campus historical question papers, 
         or student identity data are transmitted to third-party cloud LLM APIs.
   2.2 Local Storage Security:
       - Cached dossiers and local campus question databases are stored locally in the 
         user's project workspace.

3. COST & ZERO SUBSCRIPTION PRICING
   3.1 Zero API Cost Architecture:
       - Utilizes free DuckDuckGo search integration (`duckduckgo-search` / free search endpoints).
       - Utilizes open-weights local models via Ollama (`qwen2.5:7b` / `llama3.1:8b`).
       - No recurring subscriptions (OpenAI, Anthropic, Tavily, SerpAPI) required.

4. RELIABILITY, GRACEFUL DEGRADATION & ACCURACY
   4.1 Anti-Hallucination & Honest Fallbacks:
       - For newly incorporated startups or niche hiring firms with low web presence, 
         the system MUST explicitly state: "Limited public reviews found on Reddit/Glassdoor" 
         rather than inventing ratings or fabricated sentiments.
   4.2 Search Fault Tolerance:
       - If DuckDuckGo rate-limits or returns a network timeout, the pipeline falls back 
         to cached records, general web queries, or continues with available campus data 
         without crashing the backend.
   4.3 Campus Matching Precision:
       - Threshold-based fuzzy/semantic matching to ensure high confidence when pairing 
         portal company names with historical campus records (avoids false-positive matches).

5. SYSTEM RESOURCE MANAGEMENT (M4 16GB OPTIMIZATION)
   5.1 RAM Footprint:
       - Quantized 4-bit/Q4_K_M model weights in Ollama will consume ~4.5 to 5.2 GB of VRAM, 
         leaving >10 GB of unified memory available for macOS, Chrome tabs, and Python runtime.
   5.2 Backend Daemon:
       - Python FastAPI backend lightweight footprint (< 150 MB base RAM excluding Ollama).

6. USABILITY, ACCESSIBILITY & EXTENSION DESIGN
   6.1 Modern Aesthetic:
       - Side-panel drawer UI designed with clean typography, high-contrast badges for red flags, 
         clear visual hierarchy, and intuitive tabs.
   6.2 1-Click Actionability:
       - Pre-generated LinkedIn search URLs and interview questions formatted with 1-click copy 
         and direct opening.
